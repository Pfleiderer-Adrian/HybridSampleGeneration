# V3 Real + AD + Hybrid continuation

Authorized and queued 2026-11-06, behind the existing Real+AD continuation.

Results: `/mnt/results/mvtec2/experiments/anomalydiffusion_scale2x_50k/20261103/real_ad_hybrid_continuation_20261106`.

Source: `experiments/anomalydiffusion/scale2x_mixed.py`. Each worker has a plan, status, per-category logs and an immutable runtime snapshot reference. `preflight.json` records successful validation of all eight configurations and frozen hybrid provenance. The `latest_mixed_downstream_launch.json` pointer is in the parent appearance-results directory.

## Protocol

1000 draws per epoch: 500 normal, 100 real anomalous, 200 AnomalyDiffusion, 200 hybrid. Unchanged frozen V3 downstream architecture, losses, seed42, 100 epochs, batch8, optimizer, schedule, grouped splits, validation and best-checkpoint selection. The exact frozen hybrid IDs and order are supplied to the original frozen runtime. Protocol/configuration/provenance files are copied and hashed; only mixture fields and cache paths change.

Reuse the identical 1000-pair AD pool already generated for Real+AD, through a `generated` directory symlink for each category. No regeneration or alternative checkpoint selection. Last50k, 2x scale and AAR are verified from the production manifest. Inputs use the same native256 geometry and masks. Shared AD generation costs are not counted a second time.

## Scheduling and outputs

GPU0: can, fabric, fruit_jelly, rice. GPU1: sheet_metal, vial, wallplugs, walnuts. Each worker waits for its corresponding Real+AD worker's live lock and terminal status, then holds that lock throughout its own serial jobs. Each category additionally requires the matching predecessor job to be complete and its AD manifest to contain 1000 pairs with the correct split fingerprint. Jobs cannot overwrite existing downstream outputs; failed categories are recorded and other categories continue.

Workers: `gpu0_worker/` and `gpu1_worker/`, each with `status.json`, `plan.json`, `queue.log`, `jobs/<category>/status.json` and `jobs/<category>/downstream.log`. Final models/history/metrics: `downstream/real_anomalydiffusion_hybrid/<category>/downstream/dinov3_paired/<run>/`.

Each worker starts an NVML GPU energy monitor only after its predecessor releases the lock. Waiting time is excluded from the measured active session. This remains GPU-device energy only; CPU measurement has not been added here. The separate planned 100-sample efficiency benchmark is not started by this queue. Submission archives are not generated by this queue.
